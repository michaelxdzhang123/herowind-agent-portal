1. 进阶段学习目标

入门阶段重点是掌握对话式编程和基础测试能力；进阶段的重点是掌握智能体编程。

完成本阶段后，应能够做到：

  • 在终端中启动 Claude Code 或内部兼容工具。
  • 让智能体读取项目结构、理解代码依赖、定位问题文件。
  • 使用 /init 生成并维护 CLAUDE.md 项目说明文件。
  • 通过自然语言驱动 AI 完成小范围代码修改。
  • 让 AI 帮助分析测试失败原因，并完成修复和回归测试。
  • 让 AI 完成有限范围的跨文件重构。
  • 使用 /compact、/cost 等命令控制上下文长度和 Token 消耗。
  • 明确知道哪些操作可以交给 AI，哪些操作必须人工审查。

进阶段的关键不是“让 AI 自动做所有事情”，而是建立一套安全、可复查、可回滚的智能体开发流程。

2. 适用前提

本手册适用于以下人员：

  • 已经能够使用 VS Code + Continue 或类似工具完成基础代码问答。
  • 已经理解 Chat、Edit、Plan、Agent 的基本区别。
  • 已经具备 Git、Node.js、终端命令的基础使用能力。
  • 希望使用命令行智能体完成更复杂的项目级任务。
  • 内部人员需要使用本地大模型、国产模型或内部大模型网关。

不建议直接在以下场景中使用进阶段能力：

  • 项目没有 Git 管理，无法回滚。
  • 项目中有大量敏感配置文件，但没有访问限制。
  • 开发者不看 diff，直接接受 AI 的所有修改。
  • 一次性要求 AI 完成“大规模重构整个系统”。

3. 安装准备

3.1 环境要求

项目 要求 说明

Node.js v18.0+ Claude Code 依赖 Node.js 运行环境
Git 建议安装 用于版本管理、分支管理、回滚修改

执行：

git --version

期望看到类似输出：

git version 2.40.0

如果提示命令不存在，需要先安装 Git。

在正式使用前，建议准备好：

  • 项目代码仓库。
  • 可以正常运行的测试命令，例如 npm test、pytest、go test ./...。
  • 项目构建命令，例如 npm run build。

  • 项目的编码规范、提交规范、测试规范。

4. 安装 Claude Code

4.1 macOS / Linux 安装

执行：

sudo npm install -g @anthropic-ai/claude-code

如果当前用户没有 sudo 权限，可以使用 Node 版本管理工具，或者让管理员协助安装。

4.2 Windows 安装

Windows 用户建议使用 WSL 或 Git Bash：

npm install -g @anthropic-ai/claude-code

不建议在路径、权限、Shell 配置不稳定的环境中直接操作重要项目。

4.3 验证安装

执行：

claude --version

如果能显示版本号，说明命令已经安装成功。

如果提示 command not found，通常是以下原因：

  • npm 全局安装目录没有加入 PATH。
  • 当前终端没有重新加载环境变量。
  • 安装失败或权限不足。

可以尝试重新打开终端后再次执行：

claude --version

5. 登录与配置

Claude Code 有两种常见配置方式：

  1. 官方登录。
  2. 免登录配置，也就是通过兼容 Anthropic 协议的国内模型或内部网关使用。

内部开发人员优先使用第二种方式。

5.1 方式一：官方登录

适合可以正常访问 Anthropic 官方服务的用户。

执行：

claude

首次启动时，工具会引导你完成浏览器授权。

常见流程：

  1. 终端运行 claude。
  2. 按提示打开浏览器。
  3. 登录 Anthropic 账号。
  4. 完成授权。
  5. 回到终端继续使用。

官方登录方式适合网络畅通、账号权限完整的环境。

5.2 方式二：免登录配置

适合国内用户或内部模型用户。

核心思路是：

  • 跳过官方登录流程。
  • 在本机配置文件中写入已经完成初始化的信息。
  • 通过 settings.json 指向内部网关、DeepSeek、阿里云百炼或其他兼容模型。

步骤 1：创建 ~/.claude.json

macOS / Linux / WSL：

cat > ~/.claude.json <<'EOF'
{
  "hasCompletedOnboarding": true
}
EOF

Windows PowerShell 示例：

@'
{
  "hasCompletedOnboarding": true
}
'@ | Out-File -Encoding utf8 $HOME\.claude.json

该文件的作用是告诉工具：本机已经完成基础引导流程。

步骤 2：创建 ~/.claude/settings.json

macOS / Linux / WSL：

mkdir -p ~/.claude
nano ~/.claude/settings.json

Windows PowerShell：

New-Item -ItemType Directory -Force $HOME\.claude
notepad $HOME\.claude\settings.json

步骤 3：写入模型网关配置

以下为示例配置。实际字段名以团队内部模板为准。

DeepSeek 示例
{
  "env": {
    "BASE_URL": "https://api.deepseek.com/anthropic",
    "MODEL": "deepseek-chat",
    "API_KEY": "替换为你的 DeepSeek API Key"
  }
}
阿里云百炼示例
{
  "env": {
    "BASE_URL": "https://dashscope.aliyuncs.com/apps/anthropic",
    "MODEL": "qwen3.7-max",
    "API_KEY": "替换为你的阿里云百炼 API Key"
  }
}
内部网关示例
{
  "env": {
    "BASE_URL": "https://内部网关地址/anthropic",
    "MODEL": "内部模型名称",
    "API_KEY": "替换为你的内部网关 API Key"
  }
}

注意：不要把真实 API Key 提交到 Git 仓库。配置文件应只保存在本机用户目录或安全的密钥管理系统中。

7. 常用命令速查

命令 作用 使用场景
claude 启动交互式会话 进入项目后长期对话、修改、分析
claude "需求" 单次执行并退出 简短问题、一次性分析、快速生成建议

/status 查看模型和配置状态 检查当前使用的模型、配置是否正确
/clear 清空对话历史 开启新任务、避免旧上下文干扰
/undo 撤销上一次代码修改 AI 改错了、需要快速回退
@文件名 引用项目文件 让 AI 直接读取和分析指定文件

9. 如何编写和维护 CLAUDE.md

CLAUDE.md 是项目给 AI 的长期说明文件。它会影响后续 AI 的行为。

建议至少包含以下内容。

9.1 项目简介

# 项目说明

本项目是一个内部业务系统，主要用于……

主要技术栈：
- 前端：React / Vue / Next.js
- 后端：Node.js / Python / Go
- 数据库：PostgreSQL / MySQL / Redis

9.2 常用命令

## 常用命令

安装依赖：
```bash
npm install
```

启动开发服务：
```bash
npm run dev
```

运行测试：
```bash
npm test
```

构建：
```bash
npm run build
```

9.3 编码规范

## 编码规范

- 优先使用 TypeScript。
- 不允许使用 `any`，除非有明确原因。
- 新增功能必须补充测试。
- 修改公共接口时必须检查所有调用方。
- 不要在业务代码中硬编码密钥、Token、密码或内网地址。

9.4 测试规范

## 测试规范

- 修改业务逻辑后必须运行 `npm test`。
- 修改构建配置后必须运行 `npm run build`。
- 修复 bug 时应优先补充回归测试。
- 测试失败时先分析原因，不要盲目修改实现代码。

9.5 AI 使用边界

## AI 操作边界

- 修改前先说明计划。
- 不要删除用户代码，除非明确要求。
- 不要修改 `.env`、密钥文件、证书文件。
- 执行破坏性命令前必须解释风险。
- 每次修改后输出变更摘要和验证命令。

10. 基础使用流程

推荐每次任务都遵循以下流程。

10.1 新建分支

不要直接在主分支上让 AI 修改代码。

git checkout -b ai/step3-demo

10.2 启动工具

claude

10.3 先让 AI 理解任务

示例提示词：

请先阅读当前项目结构和 CLAUDE.md，理解项目的技术栈、测试命令和编码规范。
暂时不要修改任何文件。阅读完成后，请用中文总结：
1. 项目主要模块；
2. 可能的测试命令；
3. 修改代码时需要遵守的规范；
4. 你建议我下一步怎么做。

10.4 明确任务范围

不要说：

帮我优化整个项目。

建议说：

请只修改 src/api/user.ts 和 src/services/userService.ts，目标是修复用户查询接口在 userId 为空时抛出 500 的问题。
不要修改其他文件。修改后请运行 npm test，并告诉我测试结果。

10.5 审查 diff

AI 修改后，先查看 Git Diff：

git diff

重点检查：

  • 是否改了不该改的文件。
  • 是否引入硬编码。
  • 是否删除了重要逻辑。
  • 是否修改了测试但没有修复真实问题。
  • 是否新增了不必要的依赖。

10.6 运行验证命令

根据项目类型运行：

npm test
npm run build

或者：

pytest
go test ./...
mvn test

10.7 提交代码

确认无误后提交：

git add .
git commit -m "fix: 修复用户查询接口空 userId 异常"

11. 实战场景一：自动修复测试

11.1 场景说明

你运行测试时发现失败，希望 AI 帮你：

  1. 读取失败信息。
  2. 找到相关代码。
  3. 分析失败原因。
  4. 修改代码。
  5. 重新运行测试。
  6. 直到测试通过或给出无法自动修复的原因。

11.2 操作步骤

步骤 1：先运行测试

npm test

复制完整报错，包括：

  • 测试命令。
  • 报错堆栈。
  • 失败文件路径。
  • 期望值和实际值。

步骤 2：启动 Claude Code

claude

步骤 3：输入任务

我运行 npm test 后出现以下报错：

【粘贴完整报错】

请你按以下流程处理：
1. 先分析失败原因；
2. 找到最可能相关的源代码和测试文件；
3. 修改前先告诉我修改计划；
4. 只做最小必要修改；
5. 修改后运行 npm test；
6. 如果测试仍失败，继续分析并修复；
7. 最后输出修改文件列表、修改原因和测试结果。

步骤 4：审查修改

AI 修改后执行：

git diff

步骤 5：确认测试结果

npm test

11.3 注意事项

  • 不要让 AI 直接删除失败测试。
  • 不要让 AI 为了通过测试而降低断言质量。
  • 不要接受“跳过测试”“注释测试”的修复方案，除非你明确知道原因。
  • 修复 bug 时最好新增回归测试。

12. 实战场景二：跨文件重构

12.1 场景说明

跨文件重构适合以下任务：

  • 修改函数名称。
  • 修改接口参数。
  • 移动公共工具函数。
  • 拆分服务层逻辑。
  • 修改返回数据结构。

12.2 风险提醒

跨文件修改风险明显高于单文件修改，因此必须控制范围。

不要这样下达任务：

帮我重构用户模块。

建议这样下达任务：

请将 getUserInfo(userId) 重命名为 getUserProfile(userId)，并更新项目中所有调用方。
要求：
1. 先搜索所有引用，不要立即修改；
2. 列出将要修改的文件；
3. 只修改与该函数重命名相关的代码；
4. 不改变函数行为；
5. 修改后运行 npm test；
6. 输出 diff 摘要和测试结果。

12.3 操作步骤

  1. 新建 Git 分支。
  2. 启动 claude。
  3. 要求 AI 先搜索引用。
  4. 确认修改范围。
  5. 让 AI 执行修改。
  6. 查看 git diff。
  7. 运行测试和构建。
  8. 人工 Review 后提交。

12.4 验证命令示例

npm test
npm run build

TypeScript 项目建议额外运行：

npm run typecheck

13. 实战场景三：理解陌生项目

13.1 场景说明

当你接手陌生项目时，可以让 AI 先做“项目导读”，而不是直接改代码。

7. 输出一份中文项目理解报告。

要求 AI 按以下结构输出：

# 项目理解报告

## 1. 项目用途

## 2. 技术栈

## 3. 目录结构

## 4. 启动流程

## 5. 核心业务流程

## 6. 测试和构建命令

## 7. 推荐阅读文件

## 8. 潜在风险点

## 9. 后续学习建议

13.4 适合继续追问的问题

请找出用户登录流程相关的文件，并按调用顺序说明。

14. 国内用户最佳实践

14.1 官方登录连不上

推荐方案：

  • 使用免登录配置。
  • 使用内部网关。
  • 使用兼容 Anthropic 协议的国产模型。
  • 优先确认 BASE_URL、MODEL、API_KEY 是否正确。

14.2 响应慢或卡顿

可以尝试：

/compact

或者切换轻量模型：

/model

实践建议：

  • 简单解释类任务使用轻量模型。
  • 跨文件重构、复杂 bug 分析使用更强模型。
  • 长对话中途及时 /compact。
  • 一个任务完成后使用 /clear 开新上下文。

14.3 Token 消耗快

查看消耗：

/cost

降低消耗的方法：

  • 不要一次性让 AI 读取整个项目。
  • 只引用相关文件。
  • 把大任务拆成小任务。
  • 简单任务不要开启深度分析。
  • 长对话中途使用 /compact。

14.4 敏感文件泄露风险

不要让 AI 读取或输出以下文件内容：

  • .env
  • .env.local
  • .npmrc
  • id_rsa
  • *.pem
  • *.key
  • credentials.json
  • secrets.yaml
  • 数据库导出文件
  • 生产配置文件

建议在项目规则和权限设置中明确限制。

15. 安全使用规范

15.1 必须使用 Git

使用 AI 修改代码前，必须确保项目已启用 Git。

git status

如果不是 Git 仓库，应先初始化：

git init

更推荐在已有远程仓库的项目中使用。

15.2 每个 AI 任务使用独立分支

git checkout -b ai/fix-test-login

15.3 修改前先让 AI 说明计划

推荐提示词：

在修改任何文件之前，请先说明：
1. 你准备读取哪些文件；
2. 你判断问题可能在哪里；
3. 你计划修改哪些文件；
4. 你会如何验证结果。
等我确认后再修改。

15.4 必须看 diff

git diff

不要只看 AI 的总结。

15.5 不允许自动接受高风险操作

高风险操作包括：

  • 删除文件。
  • 删除测试。
  • 修改数据库迁移。
  • 修改生产配置。
  • 执行 rm -rf。
  • 修改权限、证书、密钥。
  • 大范围格式化整个项目。
  • 引入新的大型依赖。

15.6 出问题时如何回滚

撤销单个文件：

git checkout -- path/to/file

撤销所有未提交修改：

git reset --hard

删除未跟踪文件：

git clean -fd

使用这些命令前要确认没有需要保留的本地修改。

17. 常见问题排查

Q1：执行 claude 没反应或无法启动

检查：

node --version
claude --version

可能原因：

  • Node.js 版本过低。
  • npm 全局安装路径未加入 PATH。
  • 安装失败。
  • 当前终端权限不足。

处理方法：

  • 升级 Node.js 到 v18+。
  • 重新安装 Claude Code。
  • 重新打开终端。
  • 检查 PATH。

Q2：官方登录失败

可能原因：

  • 网络无法访问官方服务。
  • 浏览器授权失败。
  • 账号权限问题。

处理方法：

  • 使用免登录配置。
  • 使用内部网关或国产模型。
  • 检查 ~/.claude/settings.json。

Q3：模型不回复或报 API 错误

检查：

  • BASE_URL 是否正确。
  • MODEL 名称是否正确。
  • API_KEY 是否有效。
  • 当前网络是否能访问网关。
  • 内部网关是否支持 Anthropic 协议。

建议输入：

/status

查看当前状态。

Q4：回复很慢

处理方法：

/compact

或者：

/model

也可以缩小任务范围：

请只阅读 src/services/userService.ts，不要读取整个项目。

Q5：Token 消耗太快

查看消耗：

/cost

优化方法：

  • 减少无关上下文。
  • 使用 @文件名 精准引用文件。
  • 大任务拆成小任务。
  • 一个任务结束后 /clear。
  • 长对话中途 /compact。

Q6：AI 把代码改乱了

先不要继续让 AI 修改。

查看改动：

git diff

撤销上一次 AI 修改：

/undo

或者使用 Git 回滚：

git reset --hard

如果只想撤销某个文件：

git checkout -- path/to/file

Q7：AI 总是答非所问

通常是上下文不准确。

改进方式：

  • 明确任务目标。
  • 明确允许修改的文件范围。
  • 粘贴完整报错。
  • 说明期望输出格式。
  • 先让 AI 复述理解，再开始修改。

示例：

请先复述你对任务的理解，不要立即修改文件。如果你认为信息不足，请列出缺少的信息。

18. 进阶段练习任务

建议按以下顺序练习。

练习 1：初始化一个已有项目

目标：掌握 /init 和 CLAUDE.md。

步骤：

  1. 进入项目根目录。
  2. 运行 claude。
  3. 执行 /init。
  4. 检查并完善 CLAUDE.md。
  5. 让 AI 总结项目结构。

验收标准：

  • CLAUDE.md 内容准确。
  • 包含测试、构建、编码规范。
  • 不包含敏感信息。

练习 2：修复一个测试失败

目标：掌握测试驱动的 AI 修复流程。

步骤：

  1. 创建一个会失败的测试。
  2. 运行测试并复制完整报错。
  3. 让 AI 分析原因。
  4. 让 AI 做最小修改。
  5. 重新运行测试。
  6. 查看 diff。

验收标准：

  • 测试通过。
  • 修改范围可控。
  • 没有删除测试或降低断言质量。

练习 3：完成一次函数重命名

目标：掌握跨文件引用搜索和小范围重构。

步骤：

  1. 选择一个被多处调用的函数。
  2. 要求 AI 先搜索引用。
  3. 确认影响文件。
  4. 执行重命名。
  5. 运行测试和构建。

验收标准：

  • 所有引用都更新。
  • 行为不变。
  • 测试和构建通过。

练习 4：生成项目理解报告

目标：掌握 AI 辅助阅读陌生项目。

步骤：

  1. 找一个不熟悉的小项目。
  2. 让 AI 不修改文件，只阅读和总结。
  3. 输出项目理解报告。
  4. 人工验证报告是否准确。

验收标准：

  • 能说清楚入口文件。
  • 能说清楚核心流程。
  • 能列出测试和构建命令。

20.3 CLAUDE.md 推荐模板

# CLAUDE.md

## 项目说明

请在这里描述项目用途、核心业务和主要技术栈。

## 常用命令

- 安装依赖：`npm install`
- 启动开发：`npm run dev`
- 运行测试：`npm test`
- 构建项目：`npm run build`

## 目录结构

- `src/`：源代码目录
- `src/api/`：接口层
- `src/services/`：业务服务层
- `src/utils/`：工具函数
- `tests/`：测试目录

## 编码规范

- 优先使用清晰、可维护的实现。
- 修改公共接口时必须搜索所有调用方。
- 新增功能必须补充测试。
- 不要提交调试日志、密钥或临时文件。

## 测试规范

- 修改业务逻辑后运行测试。
- 修改构建配置后运行构建。
- 修复 bug 时优先增加回归测试。

## AI 使用约束

- 修改前先说明计划。
- 只修改与任务相关的文件。
- 不读取 `.env`、证书、密钥等敏感文件。
- 不执行高风险删除命令。
- 修改后输出变更摘要和验证结果。

最后建议

进阶段最重要的能力不是记住命令，而是形成稳定的工作习惯：

  1. 先初始化项目。
  2. 先让 AI 理解上下文。
  3. 先规划，再修改。
  4. 小范围执行。
  5. 每次看 diff。
  6. 每次跑测试。
  7. 出问题能回滚。

只要坚持这套流程，智能体可以显著提高编码、测试、重构和项目理解效率，同时把风险控制在可接受范围内。
